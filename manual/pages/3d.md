# 2D and 3D

A game is not "a 2D game" or "a 3D game" for the engine: **each entity is 2D or 3D by its components**. An entity
with an `aylo.Transform2D` lives in the 2D world, one with an `aylo.Transform3D` in the 3D world, and one game can have
both: a 3D world with a HUD and 2D sprites over it, or a 2D game with one 3D object. The [user interface](ui.md) is
neither: it is laid out on the screen and drawn over both.

Every game has both transforms: there is nothing to turn on in `project.luau`.

```luau
-- a 3D entity, one metre up and five ahead of the origin, turned a quarter to the left
ctx.commands:spawn({
	["aylo.Transform3D"] = {
		position = vector.create(0, 1, -5),
		rotation = engine.math.quat.fromEuler(0, math.rad(90), 0),
	},
})
```

## The two families

| | 2D | 3D |
|---|---|---|
| Transform | `aylo.Transform2D` | `aylo.Transform3D` |
| World pose | `aylo.GlobalTransform2D` | `aylo.GlobalTransform3D` |
| Axes | X right, **Y down**, as on the screen | **right-handed, Y up**, forward is **-Z** (as glTF files) |
| Units | world units (a pixel at zoom 1) | world units, read as **metres** |
| Rotation | an angle in radians, clockwise on screen | a quaternion `{ x, y, z, w }`, built with `engine.math.quat` |
| Scale | `{ x, y }` | `vector` or `{ x, y, z }` |

### `aylo.Transform3D`

Where a 3D entity is, relative to its parent (or to the world without one). Your systems write it.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `position` | vec3 | `0, 0, 0` | in world units (metres) |
| `rotation` | vec4 (quaternion) | `{ x = 0, y = 0, z = 0, w = 1 }`: no rotation | a unit quaternion; build it with `engine.math.quat` |
| `scale` | vec3 | `1, 1, 1` | 1 is the natural size; a negative value mirrors |

A `vec3` field reads as a Luau `vector` (`transform.position.y`) and takes a `vector` (`vector.create(0, 1, 0)`) or a
table `{ x = 0, y = 1, z = 0 }`. A `vec4` reads and takes a table `{ x, y, z, w }`.

### `aylo.GlobalTransform3D`

Where the entity is in the world, computed by the engine in `PostUpdate` from its `aylo.Transform3D` and its parents:
the same fields, read-only for your scripts. Read it after `aylo.Transform.Propagate` (in `PostUpdate`, `after = {
"aylo.Transform.Propagate" }`), or in `Update` of the next frame.

### Parents and children

`ctx.commands:setParent(child, parent)` puts a 3D child in its parent's axes: the parent's scale, then its rotation,
then its position apply to the child. The two families do not combine: a 3D entity whose parent is 2D (or the other
way round) is placed as if it had no parent, so a 2D label can sit under a 3D entity in the hierarchy without moving
with it.

### Smooth movement

`aylo.TransformInterpolation` works for both families: put it next to an `aylo.Transform3D` moved in `FixedUpdate`, and
the entity is drawn between its last two ticks, as for 2D. See [Smooth movement](systems.md#smooth-movement).

## Rotations: `engine.math.quat`

A 3D rotation is a quaternion: four numbers that are hard to write by hand, so you build them with these helpers.
Angles are in **radians** (`math.rad(90)` for a quarter turn). A vector argument is a Luau `vector` or a table
`{ x, y, z }`; a vector result is a Luau `vector`; a quaternion is a table `{ x, y, z, w }`.

| Function | Result |
|---|---|
| `quat.identity()` | no rotation |
| `quat.fromAxisAngle(axis, angle)` | `angle` around `axis` (counterclockwise looking down the axis) |
| `quat.fromEuler(x, y, z)` | `x` around X (pitch), `y` around Y (yaw), `z` around Z (roll), applied as in Unity: Z, then X, then Y |
| `quat.toEuler(q)` | `x, y, z` back, the angles `fromEuler` takes; at a pitch of 90 degrees, `z` is 0 |
| `quat.lookRotation(direction, up)` | turns forward (-Z) along `direction`, its top as close to `up` as it can (default: world up) |
| `quat.multiply(a, b)` | `b`, then `a` |
| `quat.inverse(q)` | the rotation that undoes `q` |
| `quat.rotate(q, v)` | the vector `v` turned by `q` |
| `quat.slerp(a, b, t)` | the rotation `t` of the way from `a` to `b` (0 to 1), the short way |
| `quat.normalize(q)` | `q` at length 1 |

`quat` is `engine.math.quat`; write `local quat = engine.math.quat` at the top of a file.

### Recipes

Both recipes below use components of your own with no fields, declared once:
`engine.ecs.component("game.Turret", { fields = {} })` and `engine.ecs.component("game.Spinner", { fields = {} })`.

Turn the turrets to face the centre of the world:

```luau
local quat = engine.math.quat
local target = vector.create(0, 0, 0)

engine.ecs.system("game.FaceTheCentre", {
	phase = "Update",
	query = { write = { "aylo.Transform3D" }, with = { "game.Turret" } },
	run = function(ctx)
		for _, transform in ctx.query do
			transform.rotation = quat.lookRotation(target - transform.position)
		end
	end,
})
```

Spin an entity a turn every four seconds around Y:

```luau
local quat = engine.math.quat

engine.ecs.system("game.Spin", {
	phase = "Update",
	query = { write = { "aylo.Transform3D" }, with = { "game.Spinner" } },
	run = function(ctx)
		local step = quat.fromAxisAngle(vector.create(0, 1, 0), (math.pi / 2) * ctx.time.delta)
		for _, transform in ctx.query do
			transform.rotation = quat.normalize(quat.multiply(step, transform.rotation))
		end
	end,
})
```

Move forward, whichever way the entity faces (inside a system that writes `aylo.Transform3D`, with `speed` yours):

```luau
local forward = quat.rotate(transform.rotation, vector.create(0, 0, -1))
transform.position = transform.position + forward * speed * ctx.time.fixedDelta
```

### Errors

| Message | Cause |
|---|---|
| `engine.math.quat: the quaternion must be a quaternion { x, y, z, w }` | a rotation that is not a table of four numbers |
| `engine.math.quat: the vector must be a vector or a table { x, y, z }` | a vector argument of the wrong kind (`the axis`, `the direction`, `up` name which one) |
| `engine.math.quat: the axis must not be zero` | `fromAxisAngle` with a zero axis (`the direction must not be zero` for `lookRotation`) |
| `engine.math.quat: fromEuler takes three numbers, in radians` | a missing or non-number angle |

## Moving from `aylo.Transform` to `aylo.Transform2D`

The 2D components were renamed when 3D came, so that both families read the same way: `aylo.Transform` is now
`aylo.Transform2D`, and `aylo.GlobalTransform` is `aylo.GlobalTransform2D`. Their fields did not change. Replace the
names in your scripts and capsule files; a script or a capsule that still names the old ones fails with an unknown
component. The transform plugin keeps its name, `aylo.Transform`, and so do its systems (`aylo.Transform.Propagate`).
